Getting started — install, open, run

JurisLab is a free add-in for Microsoft Word. Installing it just registers it for your own account — no administrator rights, nothing to buy, nothing sent anywhere. You need Microsoft Word (Microsoft 365, or Office 2019 or later) on Windows or Mac, and an internet connection the first time you open the pane (after that it runs offline). The whole thing takes about two minutes.

Step 1 — Download the pack for your computer

Grab the one zip for your operating system:

⬇ Download for Windows ⬇ Download for Mac

Before you install: open Word once and then close it, so it has created the folder the add-in installs into.

Step 2 — Run the installer

Unzip the download first (double-click the .zip), keeping the files together in one folder. Then follow the column for your computer:

On Windows

  1. Double-click install.bat inside the unzipped folder.
  2. If a blue “Windows protected your PC” box appears, click More info → Run anyway. (That box only shows because the file came from the internet — it’s expected.)
  3. A window says “JurisLab installed…” — press any key to close it.

Double-click does nothing? Right-click install.ps1 → Run with PowerShell instead.

On a Mac

  1. Right-click (or Control-click) install.command and choose Open — don’t double-click it the first time.
  2. You’ll get one of two boxes. If it has an Open button, click Open. If it only offers Move to Trash / Done (newer macOS), click Done, then go to Apple menu → System Settings → Privacy & Security, scroll down to Security, and click Open Anyway next to “install.command was blocked”. Enter your password / Touch ID, then Open Anyway once more.
  3. A Terminal window prints “JurisLab installed.” — press any key to close it.

This one-time approval is Apple’s rule for any installer it didn’t deliver itself — it isn’t specific to JurisLab. After the first time, it’s a normal double-click.

Why the security prompt? Neither installer needs admin rights and neither sends anything anywhere — it only copies one small file into Word’s own add-in folder. Windows and macOS simply ask you to confirm any installer downloaded from the web. Approving it once is all it takes.

Step 3 — Restart Word, then open the pane

  1. Fully quit Word — every window (on Mac use ⌘-Q, not just the red dot). Word only notices a new add-in on a cold start; this is the single most common reason it seems “not installed”.
  2. Reopen Word and go to the Insert tab → Add-ins (the My Add-ins dropdown) → click JurisLab. On Windows it may sit under Developer Add-ins.
  3. The pane opens on the side, on the Home screen showing all 26 tools as cards, grouped by area.

Step 4 — Run it (a 10-second test)

Put your cursor in the document, click the Chemical card, type H2O, and press Insert formatted text — you should get H₂O in your document. That’s the whole loop: pick a tool, type, insert. If that worked, everything works.

Appearance. The pane follows Word's own theme — switch Word to Black or Dark Gray and the pane goes dark to match. There is an Appearance control at the foot of the pane if you would rather force Light or Dark. One deliberate exception: the structure, plot and spectra previews keep their white background in dark mode. They are showing you artwork that goes into your document as black-on-white line art, and a dark preview would misrepresent what you are about to insert.

Only that first load needs internet — the add-in fetches its code once, then everything you type is computed on your own machine. If it ever misbehaves, jump to Troubleshooting at the bottom.

The core loop

Every tool works the same way, so once you’ve learned one you’ve learned all of them:

  1. Put your cursor where you want the content to land in your document.
  2. Pick a tool — click a card on the Home screen, or use the dropdown at the top. The Home filter chips (All / Science / Legal) narrow the cards to your kind of work; nothing is removed, just hidden.
  3. Type. A live preview appears as you go, showing exactly what will be inserted.
  4. Insert. The button drops it at your cursor. If it isn’t what you wanted, a single Ctrl-Z (⌘-Z on a Mac) removes it cleanly.
Try it: open Chemical, type H2O → the preview shows H₂O → Insert formatted text. Then type aspirin → a 2D structure appears with its formula and molecular weight.

Chemistry & structures

Five tools — Chemical, Build, Reaction, Mass Spec, Spectra.

Chemical — formulas, 2D structures, properties & pKa

Two things in one panel. Type a formula and it typesets itself: H2O → H₂O, Ca(OH)2 → Ca(OH)₂, 2H2O keeps the coefficient full-size, SO4^2- → SO₄²⁻, Na+ → Na⁺, [Fe(CN)6]3- → the bracketed ion. Type a name, formula or SMILES and it resolves a 2D structure with a full readout.

  • Validation against a complete 118-element table: real-element check, balanced brackets, nested groups (K4[Fe(CN)6]), hydrate dots (CuSO4·5H2O), net charge, molecular weight, and the normalized Hill formula. The readout is either ✓ Valid — CaH2O2, M = 74.093 g/mol or ⚠ with the exact error.
  • Structure drawn by OpenChemLib; isomeric SMILES (C[C@@H](N)C(=O)O) is drawn with wedge/hash bonds. Known compounds are recognised back from the drawing (a dictionary lookup, not a general IUPAC namer).
  • Physicochemical properties: MW, heavy-atom count, cLogP, logS, tPSA, H-bond donors/acceptors, rotatable bonds.
  • Druglikeness: Lipinski Rule of Five (≤1 violation passes) and Veber (rotatable ≤10, tPSA ≤140), compared on unrounded values.
  • pKa by exact ionizable-group detection on the atom graph (~a dozen groups, including polyprotic acids), substituent-corrected for aromatic acids/bases (Hammett) and aliphatic acids (inductive) so the value is specific to your molecule — e.g. p-nitrophenol ≈ 7.15 vs phenol 9.99, chloroacetic ≈ 2.87 vs acetic 4.76 — with the derivation shown, plus the estimated net charge at pH 7.4.
  • Periodic table & atomic structure. Type a symbol, a name or an atomic number and pick one of four views: an element summary, a Bohr model, an orbital filling diagram, or the table itself (118 cells, with the f-block drawn beneath). What is computed — electron configuration, shell occupancy, block, group and period — comes from the aufbau rule, with the Madelung order generated from its own statement (increasing n+l, then increasing n) rather than typed out. What is fetched — names, measured configurations, oxidation states, electronegativity, ionisation energy, electron affinity, atomic radius and standard state — comes from PubChem via a committed script that refuses to write unless all 118 symbols match the already-verified table in order. Atomic weights stay the held IUPAC values, which differ from PubChem's for lithium and for the elements with no stable isotope, by convention rather than error.
Three places it refuses to overclaim. Aufbau configurations are labelled predictions: they agree with measurement for 88 of 118 elements, and the 30 that differ are exactly the classic exceptions (Cr, Cu, Nb, Mo, Ru, Rh, Pd, Ag, La, Ce, Gd, Pt, Au, Ac, Th, Pa, U, Np, Cm and the rest), so where the two disagree both are shown. The Bohr model says it is a 1913 teaching model, not current physics. And the group-3 question (lanthanum or lutetium) is genuinely unsettled, so the f-series sits outside the numbered groups and the figure explains why instead of taking a side. Melting and boiling points, density, crystal structure, Mohs hardness and spectral emission lines are reported as absent, each with the reason — they need a citation, and a reference that quietly omits a property is indistinguishable from one that has no data.
Try it: aspirin → structure, formula C₉H₈O₄, MW, druglikeness, and “Carboxylic acid — acidic, pKa ≈ 4.5”. Ca(OH)2 → ✓ Valid — CaH2O2, M = 74.093 g/mol. Fe → period 4, group 8, d-block; [Ar]4s² 3d⁶; shells K 2, L 8, M 14, N 2.

Inserts: formatted formula (text), structure (picture with provenance), recognised name (text), or the properties + pKa block (text with its caveats).

Honest about estimates. cLogP/logS are model predictions (RMSE ≈ 0.4 / 0.7 log units; shown as n/a for inorganics). pKa detection is exact, and for aromatic acids/bases and aliphatic acids the value is substituent-corrected — a Hammett (ρ·Σσ) or inductive adjustment specific to your molecule, shown with its derivation (e.g. p-nitrophenol ≈ 7.15, not phenol’s 9.99). Other groups still use the typical group value. Online IUPAC lookup (OPSIN) is the one feature that leaves the machine, and it always asks first.

Build — structures from atoms/bonds, Markush & molfiles

Draw a structure by describing it, or paste an MDL molfile. Built for patent genus/Markush work.

  • Atom/bond DSL: atoms: C C O (1-indexed) and bonds: 1-2 2=3 where -/=/# are single/double/triple, ~ is any, i>j/i<j are wedge/hash. Atoms carry charge (N+, Fe2+); hydrogens auto-fill.
  • Markush / generic atoms: [C,N] variable-atom list, X halogen, A any atom, Q any heteroatom, R1/R2… R-groups.
  • Query features in trailing braces: {ar} aromatic, {r6} ring size 6, {har} heteroaromatic, {ring}/{chain}, substitution constraints — on atoms and bonds.
  • Molfile: paste any MDL V2000/V3000 (auto-detected).
  • R-group legend generated as an inline line or a two-column table, with shorthand expansion (C1-6 alkyl → C₁–C₆ alkyl, opt sub phenyl → optionally substituted phenyl).
Try it: atoms: C O O / bonds: 1=2 1=3 → CO₂. A ring with [C,N] spans benzene and pyridine and is reported as a generic structure.

Inserts: the structure (picture with provenance), optionally followed by the R-group legend (paragraph or table). Query structures report MW as “generic structure”, by design.

Reaction — reaction-scheme layout

Compose a scheme from names/SMILES: reactants + reactants >> products ; over ; under. Arrows: >>/-> forward, <=>/⇌ reversible, <- retrosynthetic; multi-stage chains are supported. The two optional ; fields are text over/under the first arrow.

Try it: CCO + CC(=O)O >> CC(=O)OCC ; H2SO4 ; reflux → ethanol + acetic acid → ethyl acetate, “H2SO4” above and “reflux” below a forward arrow.

Inserts: the whole scheme as one picture with provenance.

Layout only. Reaction draws what you type — it does not balance equations, predict products, or check feasibility. Arrow type and conditions are yours to state.

Mass Spec — exact mass, isotope pattern, adducts

From a name, formula or SMILES:

  • Monoisotopic and average mass.
  • Isotope pattern by exact discrete convolution over NIST abundances — peaks M, M+1, M+2… as offset, exact centroid mass, and intensity normalised to base = 100.
  • Adduct m/z for nine ESI adducts: [M+H]⁺, [M+Na]⁺, [M+K]⁺, [M+NH₄]⁺, [M+2H]²⁺, [M−H]⁻, [M+Cl]⁻, [M+HCOO]⁻, [M−2H]²⁻ — with electron-mass correction. Omitted automatically for an already-charged input.
Try it: glucose → monoisotopic 180.0423, average 180.159; [M+H]⁺ 181.0495, [M+Na]⁺ 203.0315, [M−H]⁻ 179.0350. A chlorinated compound shows the tell-tale ~32% M+2 peak.

Inserts: a text summary (masses, pattern with %, adducts). Untabled elements are excluded from the pattern shape only, with a note; masses stay exact.

Spectra — predicted NMR, 2D, IR, UV-Vis & MS fragmentation

Pick a spectrum type, type a name or SMILES, and get a prediction with an assignment for every signal. Seven kinds:

KindWhat you get
¹H NMRSymmetry-distinct signals: shift, integration, multiplicity — with coupling refinement adding J values and multiplet names (dd, td…).
¹³C NMRGrant–Paul additivity (sp³) + aromatic increments; carbonyl classes separated (ketone ≈205, ester ≈171…).
COSY (2D)¹H–¹H cross-peaks from the exact coupling topology, with typical J by relationship (ortho ≈7.8, meta ≈1.5 Hz…).
HSQC (2D)One-bond ¹H–¹³C correlations — one peak per protonated carbon (topology exact).
IRCharacteristic group frequencies with range, intensity, broad flag; carbonyl class separation; conjugation lowers C=O.
UV-Visπ→π* λmax by Woodward–Fieser, every increment listed for audit; “transparent” out of domain rather than a guess.

Try it: toluene, ¹H → δ 2.4 (3H, s, CH₃ on Ph) plus the aromatic signals. toluene, EI-MS → tropylium m/z 91.0542 ranked high (its real base peak). acetophenone, IR → C=O ≈1690, labelled conjugated.

Inserts: a data table (with caveats), and where chartable a spectrum image — NMR stick, IR trace, MS stick, or a 2D COSY/HSQC map.

Open a measured spectrum instead. Below the predicted tools there is an Open a .jdx / .dx file button. Everything above it is estimated from structure; this is the opposite — a JCAMP-DX file straight from your instrument, plotted exactly as written and labelled measured on the chart so the two can never be confused. The file is read on your machine and nothing is uploaded. The axis follows the technique rather than the file: IR, Raman and NMR are drawn with their x quantity increasing leftward, which is how they are conventionally plotted, so a mirrored spectrum — which would look perfectly plausible — cannot happen. A long trace is reduced for drawing by keeping the minimum and maximum of every bucket, so a one-point peak survives; keeping every nth point instead would drop narrow bands silently.

Read before using Spectra. These are estimates from published additivity rules — structure recognition is exact, the numbers carry real uncertainty (¹H ±0.2–0.4 ppm, ¹³C ±2–4 ppm, IR ±10–30 cm⁻¹, UV-Vis ±5 nm in domain). OH/NH shifts are nominal ranges; aliphatic J is the ~7 Hz freely-rotating average; alkene J is nominal without defined cis/trans; the IR fingerprint region below ~1500 cm⁻¹ is not predicted; MS “likelihood” is a ranking, not an intensity. Use it to assign peaks you already have. The caveat block is never omitted.

Math & units

Six tools — Math, Solve, Units, Plot, Stats, Analyze.

Math — native Word equations

Type x^2 + y^2 and insert a real Word equation (click it and Equation Tools appear — editable, not a picture). If the host is too old or the expression won’t parse, it falls back to formatted text and tells you.

  • Fractions a/b, scripts x^{n+1}, roots sqrt(x)/root(n,x), abs/floor/ceil/norm.
  • N-ary sum(i=1,n,e) Σ, prod ∏, int(a,b,e) ∫ (plus oint/iint), lim(x->0, e).
  • Matrices matrix(a,b; c,d) (and pmatrix/bmatrix/vmatrix), cases(…) piecewise, multi-line align(a=b; c=d), accents bar/hat/vec, Dirac bra/ket/braket.
  • Greek by name, logic/set-theory symbols, and operators (<= → ≤, -> → →, +- → ±). Implicit multiplication (2x, 2(x+1)).
  • Formula library dropdown with 19 categories (statistics, calculus, physics, engineering, three finance groups…). LaTeX import (paste, convert) and copy-as-LaTeX out. Tick Number this equation for an auto-incrementing (I), (II)….
Coming from LaTeX? Paste \frac{-b \pm \sqrt{b^2-4ac}}{2a} and convert it to a Word equation — the quadratic formula as a true stacked fraction with a radical.

Inserts: a native Word equation object, or inline formatted-text runs matching the preview.

Solve — equations, calculus, geometry & topology

A no-code solver that runs entirely on your machine. Pick what to do from the dropdown:

Two bodies. Distance/rate/time problems handle the closing case — two things approaching or separating, where the speeds add — and show the combined rate in the working. Anything the templates cannot actually represent is refused rather than approximated: two distances, two times, or two speeds with no stated geometry all produce a refusal instead of an answer built from whichever number appeared first.

  • Solve an equation — x^2 - 5x + 6 = 0 → x = 3, 2 exactly. Linear and quadratic are closed-form; for any higher-degree polynomial you get every root, real and complex (x^3 - 1 = 0 → 1 and −0.5 ± 0.866i), with repeated roots marked ×2/×3. Only genuinely transcendental equations (cos(x) = 0) are limited to real roots in a scanned range. Identities and no-solution cases are reported as such.
  • Rearrange a formula — type an equation with several symbols and the pane offers a chip per unknown: F = m*a → Solve for: F · m · a. Pick a and you get a = F/m, exactly, with the other symbols carried through. Quadratic targets return both ± branches of the quadratic formula symbolically. Every division the rearrangement introduces states its condition (requires m ≠ 0), and every answer is checked by substituting it back into the original equation.
  • Differentiate — a symbolic derivative: sin(x^2) → 2*x*cos(x^2) (chain rule). Results are collected and cancelled by the CAS core, so sin(x)*cos(x) differentiates to cos(x)^2 - sin(x)^2 rather than an unreduced sum.
  • Definite integral — exact where a closed form exists (it shows the antiderivative F(x)): x^2 from 0 to 3 → 9. Falls back to numeric (adaptive Simpson) only when no rule applies. Limits may be expressions like pi/2.
  • Word problem — offline templates for percentages (12 is what percent of 48? → 25%), distance = rate × time, and simple “a number …” sentences (twice a number plus 7 is 15 → builds 2*n + 7 = 15, n = 4). Also successive-share problems — a pie is divided among 100 guests; guest 1 gets 1%, guest 2 gets 2% of what’s left, and so on — who gets the largest piece? — solved by evaluating the whole sequence, with the general term and the winning share shown.
  • Systems, inequalities, limits and series — several equations at once (exactly, by row reduction, where they are linear); an inequality solved by sign analysis rather than by multiplying through, so 1/x < 1 correctly keeps the negative branch that a naive multiply loses; limits including the indeterminate forms, checking BOTH sides before reporting anything; and Taylor/Maclaurin series to any order.
  • Geometry — exact coordinate geometry in 2D and 3D on rational arithmetic, so lengths keep their surds and areas stay exact. Triangle solving (SSS/SAS/ASA/AAS, and the SSA ambiguous case returning two solutions, one, or none), conic classification with degenerate cases named, polygons, triangle centres with the Euler line verified exactly on every call, and in 3D the four-way classification of two lines — identical, parallel, intersecting or skew — which exact arithmetic settles with no tolerance at all.
  • Algebraic topology — integral homology of a named space or your own complex, by Smith Normal Form over ℤ, so torsion survives: H₁(ℝP²) = ℤ/2, which a field-coefficient Betti number silently discards. The Euler characteristic is cross-checked two independent ways on every result. Paste a point cloud instead and you get a persistence barcode — which holes in your data are real and which are sampling noise. Plus knot polynomials from a braid word (Jones, and the Alexander polynomial with its determinant and symmetry check), π₁ as a Wirtinger presentation, characteristic classes, cobordism, Serre spectral sequence E₂ pages and the stable homotopy table.

Inserts: the solution as text — the variable, each root/answer, the method label, and steps.

Exact answers are labelled exact; numeric answers state their limits (a transcendental equation reports only the real roots it bracketed in the scanned range; integration falls back to adaptive Simpson only when no closed form applies, and says so). Word problems say so when they can’t template a problem rather than inventing an answer — the honest half of a “both, offline first” design. An optional online AI solver for free-form problems can be added. The topology side is blunter still, because it has to be: a spectral sequence reports its E₂ page with every possible differential marked undetermined and never hands over H*(E), since the Hopf fibration and the trivial bundle share a page and differ only in that differential; stable homotopy groups are a cited table, labelled a lookup, and say “not tabulated here” past their range rather than continuing the pattern; and the word problem for groups and homeomorphism in dimension four and above are undecidable, so π₁ is presented and abelianised but never identified.

Units — SI typesetting & conversion

  • Typesetting: 9.81 m/s^2 → 9.81 m/s², uncertainties 5.0 +- 0.2 kg → 5.0 ± 0.2 kg, scientific notation 1.2e-3 mol/L → 1.2 × 10⁻³ mol/L, symbol fixes (ohm → Ω, degC → °C, um → µm, angstrom → Å).
  • Conversion across length, mass (incl. Da/kDa), time, temperature (°C/°F offsets handled), volume, pressure, energy, amount, angle, and electrical units — including compound units (km/h → m/s, g/mol → kg/mol). Results are given to 4 significant figures.
Try it: 1 km → mi → 0.6214 mi; 100 °C → °F → 212 °F.

Inserts: the typeset quantity or the conversion line. Incompatible or unknown units are refused, not fudged.

Plot — function & data charts

  • Functions: one or more expressions separated by ; (each its own labelled line), over an x-range. Full function set (trig, hyperbolic, exp/log/sqrt, min/max/hypot…), constants pi/e/tau. No eval — safe expression parsing.
  • Data: one point per line, x y or x y err (the third column draws an error bar). Functions and data can overlay, with a legend.
Try it: x^2; exp(-x^2) → two labelled curves with a legend; data lines 1 2 / 2 4.1 0.3 → scatter points with an error bar.

Inserts: the chart as a PNG picture, drawn entirely offline.

Logarithmic axes. Either axis can be base-10 log — for dose–response, titrations, kinetics, and anything spanning decades. A log axis cannot show zero or a negative value, so it says how many points it dropped and on which axis rather than quietly plotting a subset; a dilution series with a zero-concentration control hits that on the first try.

Stats — tests, regression & uncertainty

Pick a test, paste your numbers (space/comma/newline separated), get a paper-ready result with a real p-value computed from distribution functions (not table lookups). Twenty-one tests in all:

  • Descriptive statistics (n, mean, SEM, SD, median, 95% CI, CV); two-sample t-test (Welch or Student); paired t-test; one-way ANOVA; linear regression (slope/intercept/R²/slope p).
  • Non-parametric: Mann–Whitney U and Wilcoxon signed-rank (normal approximation, tie- and continuity-corrected).
  • Chi-square goodness-of-fit and test of independence (r×c); two-way ANOVA (balanced, with replication).
  • Utilities: uncertainty propagation (value ± combined 1σ, with the largest-contributing variable), and multiple-comparison correction (Benjamini–Hochberg / Holm / Bonferroni).
  • Effect sizes. Every t-test reports Cohen's d and a 95% confidence interval on the difference, which journals require alongside p — p alone confounds the size of an effect with the size of the sample. The paired test reports dz and labels it as such, because the two are not comparable.
  • Check test assumptions. D'Agostino–Pearson K² for normality and Brown–Forsythe for equal variances. Every warning names the alternative to use rather than just complaining, and the t-tests carry the verdict underneath their own p-value. Below n = 20 it refuses to report rather than returning a number with no power behind it.
  • Non-parametric beyond two groups: Kruskal–Wallis with Dunn post-hoc (tie-corrected; the post-hoc appears only when the overall test is significant) and Friedman for repeated measures.
  • Post-hoc: Tukey HSD for all pairs, and Dunnett for every treatment against one control — which corrects for the comparisons you wanted rather than all k(k−1)/2, and is the difference between a significant result and none in a typical dose study.
  • Multiple and polynomial regression — any number of predictors, solved by QR, with residual and normal Q–Q plots drawn under the result. Those plots are the point: a curved relationship fitted with a straight line posts a respectable R² while being systematically wrong at both ends, and no summary number reveals it. Adjusted R² sits beside R² because plain R² can only ever rise when you add a predictor.
  • Survival analysis: Kaplan–Meier with Greenwood confidence intervals, the log-rank test, and a hazard ratio. Censored subjects count toward the risk set up to their time and not after — they are neither events nor discarded. Median survival reports NOT REACHED when the curve never falls to 50%, rather than substituting the longest observed time.
Try it: one-way ANOVA on 1 2 3 / 4 5 6 / 7 8 9 → F(2, 6) = 27.00, p ≈ .001. Regression on x = 1..5, y = 2.1 3.9 6.1 8.0 9.9 → slope ≈ 1.97, R² ≈ 0.999.

Inserts: the result block as text (APA-style, e.g. t(18) = 2.41, p = .027). Zero-variance or too-few-points inputs get a clear guard message.

Analyze — a no-code numerical workbench

Twenty sub-tools, each pre-filled with a worked example; results (matrices, text, and inline plots) insert at the cursor.

  • Linear algebra: solve A·x = b, inverse, determinant/rank/trace, eigenvalues (symmetric — with vectors; and any square matrix — complex pairs as a ± bi), QR, SVD, matrix multiply, transpose, and a MATLAB-style matrix expression evaluator (A*inv(B) + 2*A').
  • Optimization: minimise a typed function (Nelder–Mead); reports the minimum, its location, and whether it converged.
  • FFT: radix-2 amplitude spectrum + top-3 dominant frequencies + a chart.
  • FFT filter: de-noise a uniformly sampled signal — low-pass, high-pass and band-pass keep a band, band-stop removes one. The filtered trace is plotted over the original, so you can see what was taken out rather than trusting that it was noise. The transition is a raised cosine rather than a brick wall, because a brick wall rings, and a cutoff at or above Nyquist is refused with the reason — nothing above it was ever sampled.
  • Data → insights: paste a table → per-column summaries, Pearson r (with p) and Spearman ρ for every numeric pair, trends vs row order, outlier/missing flags, and a plain-language write-up. Every figure traces to an input cell.
  • Solve an ODE / system: type the equation you have — higher order is auto-reduced to a first-order system (up to order 6). Solver Auto starts explicit (RK45) and switches to an implicit stiff method (RODAS4) mid-run when the problem turns stiff. Optional report-at times (computed exactly, not interpolated) and a “stop when this hits zero” terminal event.
  • Boundary value problem: y″ = f(x, y, y′) with y fixed at both ends, by finite differences (robust) or shooting. Reports the solution, y′, and an observed convergence order taken from three grids — about 2 for a smooth problem, and if it is not, the result says the error estimate should not be trusted. It also states plainly that a BVP may have no solution, one, or infinitely many, so what you get is one solution and it cannot tell you which case you are in.
  • PDEs — heat, wave, Laplace/Poisson: uₜ = αuₓₓ on a rod with both ends held, uₜₜ = c²uₓₓ for a vibrating string, and the steady field on a rectangle. Crank–Nicolson is the default for heat because it is unconditionally stable; explicit FTCS is offered but is stable only for r = αΔt/Δx² ≤ ½, so Δt is reduced to satisfy that and the result says it was. For the wave equation the Courant number cannot exceed 1, and at exactly 1 the scheme is exact for the 1D wave equation.
  • Differential-algebraic system: y′ = f(t, y, z) together with 0 = g(t, y, z), semi-explicit and index 1 only. The constraint is imposed at every step so it holds by construction and never drifts. Initial values must satisfy the constraint — unlike an ODE you cannot choose them freely — and inconsistent ones are projected onto it and reported, showing both the original residual and where the run actually started. An index-2-or-higher system is refused by name, because an index-1 method run on one can return a plausible answer that slides steadily off its own constraint.
Try it: eigenvalues (general) of 0 -1 / 1 0 → ±i. Optimise the Rosenbrock function from x=-1.2, y=1 → min ≈ 0 at (1, 1). ODE y'' = -y, y=1, y'=0, 0..2π → y = cos t, ending y ≈ 1 (“auto-reduced to 2 states”). Boundary value problem y'' = -y on 0, 1.5707963 with y = 0, 1 → sin x, reported with convergence order 2.00. DAE y' = -z with constraint z - y → y = e⁻ᵗ, z tracking y exactly.

Inserts: text lines, matrices as editable Word tables, and inline plots (FFT spectrum, ODE trajectory). Singular matrices are reported as exactly that, never faked.

Engineering

One tool — but the largest in JurisLab, with 101 calculators across eighteen disciplines.

Engineering — 101 calculators in eighteen disciplines

The disciplines are shown as panels rather than one long dropdown, so you pick the bench first and the calculator second. Every calculator is pre-filled with a worked example, and each states its units and its assumptions with the answer.

  • Structural & solids (6): beam analysis (reactions, shear, moment, deflection), cross-section properties & stress, principal stresses & failure, truss analysis by the method of joints, column buckling, shaft torsion.
  • Fatigue & machine design (3): endurance limit & notch factor, mean stress & factor of safety, finite life & cumulative damage.
  • Fluids (4): pipe flow & head loss, open-channel flow, pump NPSH & cavitation, compressible flow & choking.
  • Thermal (5): composite wall / pipe insulation, heat exchanger (LMTD sizing), ideal-gas processes, power cycles, Rankine & refrigeration with a Carnot check.
  • Energy & power (17): wind turbine power with the Betz limit enforced (a claimed Cp above 16/27 is refused as physically impossible), wind shear to hub height by the power law AND the log law with their disagreement reported, Weibull wind statistics with a capacity-factor estimate (the mean speed always undersells a site — the energy pattern factor says by how much), solar PV output with NOCT cell-temperature derating, PV fill factor from datasheet I-V points, sun position and day length from pure astronomy including the extraterrestrial ceiling H₀, hydropower on the net head, battery pack series/parallel design with C-rate and the Peukert correction shown beside the uncorrected runtime, off-grid storage sizing where the losses compound upstream, plus LCOS per kWh discharged, combustion stoichiometry computed exactly from the fuel's molecular formula via the real IUPAC atomic weights (methane AFR 17.1, octane 15.0 — the heating value is your measured input, never a correlation), flue-gas analysis that turns a measured dry O₂ reading into the excess air, three-phase power (P = √3·V·I·pf, connection-independent on line quantities), power factor correction with delta and wye capacitor sizing, cable voltage drop (copper at the definitional 100% IACS; AWG computed from the gauge's exact geometric law), levelized cost of energy where the energy is discounted too, capacity factor, and adiabatic flame temperature (no dissociation, and it says so) on GRI-Mech NASA polynomials cross-checked against JANAF landmarks in the test suite — the heating value stays your measured input. Deliberately no insolation tables, no fuel property tables, no battery chemistry curves — those are site and datasheet measurements you supply, and the tool does the arithmetic and the physical-bound checks around them. Grid units convert throughout: kWh/MWh/GWh, BTU and therms, amp-hours, gallons per minute.
  • Audio & acoustics (7): sampling & aliasing (sharing the engine the Biomedical signal tool uses), quantisation and dynamic range (SNR = 6.02n + 1.76 dB, and the figure assumes a FULL-SCALE signal), decibel conversion that always shows both the 10·log and 20·log readings because picking the wrong one is the commonest error in the subject, sound level with distance and incoherent summing (two identical sources are +3 dB, not +6), reverberation by Sabine and Eyring together — Sabine never reaches zero however absorbent the room, which is impossible, and Eyring fixes exactly that — room modes labelled axial/tangential/oblique because axial modes carry the energy that is actually heard, and comb filtering from a delayed reflection, which equalisation cannot fix because the cause is arrival time. Absorption coefficients and driver parameters are your measured inputs, per frequency band.
  • Video & display (7): bitrate and storage budgets where 4:2:0 is a 50% reduction, not 25% (it halves chroma both horizontally and vertically) and the compression ratio is your input rather than a built-in codec-efficiency table; resolution, pixel density and the distance past which the grid is unresolvable, because the eye is the limit, not the panel; HDR luminance on the absolute PQ curve, where contrast is dominated by the black level rather than the peak; PSNR, which is comparable only within one clip at one resolution; streaming buffers, where startup uses the surplus bandwidth because playback drains the buffer while it fills; and end-to-end latency quantised to the display refresh, so shaving time off a stage changes nothing unless it crosses a boundary. No codec implementation and no trained perceptual metric.
  • Electronics (5): DC operating point, AC response & Bode plot, op-amp circuits, analogue filter design, truth table & Boolean minimisation.
  • Control systems (4): poles, zeros & stability, step & impulse response, frequency response & margins, PID & closed loop.
  • Vibration (4): free response & damping, forced response & isolation, natural frequencies & mode shapes, forced response of a multi-degree-of-freedom system.
  • Chips & semiconductors (4): switching & leakage power, junction temperature & thermal path, interconnect RC delay, setup/hold timing closure. Three conventions are stated rather than assumed, because each is a silent factor: the activity factor counts 0→1 transitions per cycle (the other form halves the formula), energy per transition is C·V² and not ½C·V² (half is merely stored), and clock skew helps setup but hurts hold — a hold slack computed with the setup sign is positive for a part that fails in silicon, and slowing the clock cannot fix it. Leakage is your measured input, not a prediction.
  • Computation & information (6): parallel speedup (Amdahl & Gustafson), Shannon entropy & redundancy, channel capacity, hash-collision/birthday bound, floating-point precision & cancellation, empirical runtime scaling. Every bound here is a theorem rather than a fitted constant, and what goes wrong is that the laws are easy to state and easy to apply to the wrong question — so each says which question it answers. Amdahl and Gustafson do not disagree: one holds the problem fixed, the other the time, and their parallel fractions are fractions of different totals. A collision probability is not n²/2d — that is an expectation, and it passes 1 while the probability is still well below it. Machine epsilon is the spacing at 1.0, not an absolute error bound, which is exactly why subtracting two nearly equal large numbers destroys precision. And an asymptotic class predicts a ratio, never an absolute time.
  • Robotics & kinematics (6): planar forward kinematics, 2R inverse kinematics, the Jacobian with singularity and static torque, Denavit-Hartenberg forward kinematics, trapezoidal motion profiles, differential-drive kinematics. What goes wrong in kinematics is not arithmetic but multiplicity and domain, so each is named rather than papered over: a 2R arm has two IK solutions and both are returned, distinguished by the sign of θ₂ because “elbow up/down” flips with the base frame; a target outside the reachable annulus has none, and is refused rather than clamped to the workspace edge, which would return a pose that does not reach the point asked for; at full extension and full fold the two solutions coincide and the Jacobian loses rank, so an inverse-Jacobian controller divides by nearly zero; and at gimbal lock roll and yaw stop being separable, so no roll/pitch/yaw triple is reported at all — the rotation matrix, which is unambiguous, is given instead.
  • Aviation & avionics (5): standard atmosphere, airspeeds (TAS/EAS/CAS/Mach), lift & drag polar with stall speed, level-turn load factor & radius, climb rate & power-off glide. The atmosphere is a layered definition, not a formula — seven layers to 84.852 km, each with its own lapse rate, and the barometric relation changes form at every isothermal boundary; the layer table is walked rather than approximated, and the base pressures are generated from the recurrence rather than typed so the profile cannot have a step in it. Altitude is entered as geometric and converted to the geopotential the model is defined in. An ISA offset moves temperature and density but not pressure — which is why hot-and-high hurts performance. IAS is not computed, because CAS→IAS is instrument and position error published on a per-airframe correction card, and inventing it would be exactly the failure this project avoids elsewhere.
  • Optics & photonics (8): photon energy/wavelength/frequency, Gaussian beam propagation, ABCD ray-matrix systems, two-mirror cavity stability & mode size, pulse energy/peak power/fluence, refraction with TIR & Brewster, Airy disc & grating orders, step-index fibre NA/V/cutoff. Conventions are stated in every result because they are where these calculations go wrong: w is a 1/e² radius, divergence is a half-angle, peak fluence is twice the energy over the 1/e² area, and a Gaussian pulse peaks at 0.939 E/τ, not E/τ. Refractive index is your input — there is no index table, because n is dispersive and one recalled rather than cited would be unverifiable.
  • Quantum optics (4): two-qubit entanglement (concurrence, entanglement entropy, Schmidt spectrum), CHSH Bell test, Werner state, BB84 secure key rate. Every bound is a theorem rather than a fitted constant, and is derived rather than typed: the classical CHSH bound of 2 and Tsirelson's 2√2 (a value above that is reported as an error, not a better result), the Werner thresholds at p = 1/3 for entanglement and p = 0.707 for a CHSH violation — the gap between them being the range where a state is entangled and no Bell test can show it — and BB84's ~11% threshold, computed as the root of the key-rate formula so the two cannot disagree.
  • Biomedical (3): haemodynamics, joint biomechanics, signal sampling & aliasing.
  • Pharmacokinetics (3): dose & concentration curve, steady state & loading dose, non-compartmental analysis of measured data.

Exact where exact is possible. Beams and trusses compute over rationals, not floats, so a propped cantilever under a uniform load reports 3/8 wL rather than 0.37499999996, a zero-force member comes back as an exact zero rather than something under a tolerance, and a DC divider reports 10/3 V rather than 3.3333. Statically indeterminate beams need no force method and no superposition table — compatibility is solved alongside equilibrium in one step. Every numeric field also takes an exact fraction (roller 8/3, point 30 at 8/3), which is the point of a rational engine: a support at L/3 typed as 2.6666666667 puts a rounding error into the input of an exact solver. Supports may also be elastic or settling (roller 8 k=5e4, roller 8 settle=0.01) and stay exact; those two cases need EI and say why, because a spring or a settlement makes the reactions genuinely depend on the beam's own stiffness rather than cancelling out as they do on rigid supports.

Units are converted and the conversion is reported. A bare number is read in the unit the field names and flagged as assumed; write another unit (200 GPa, 1e6 mm^4, 50 ksi, 68 °F) and it is converted for you and told to you; a unit of the wrong quantity is refused by name rather than silently dropped. This closed a real trap: cross-sections report I in mm⁴ because that is what section tables print, buckling wants m⁴, and pasting one into the other was wrong by a factor of 10¹² while looking entirely plausible. Beam and truss deliberately do not convert, because a conversion is a floating-point multiply that would destroy the exactness those two engines exist for. Temperature is handled separately everywhere it appears, since every efficiency here is a ratio of absolute temperatures and a Celsius value used as kelvin gives a confident, completely wrong answer.

It refuses in the vocabulary of the subject, not the matrix. A node with no DC path to ground is named as that, because it is the commonest netlist mistake. A mechanism, an indeterminate truss and a critical form — where the member count balances and the structure still collapses — are each named, which matters because counting members is exactly what cannot catch the third. Laminar pipe flow says the roughness was ignored, because a laminar flow cannot feel the wall; the transition band from Re 2300 to 4000 returns a number and says it is not repeatable.

Multi-DOF forced response. Steady-state amplitude and phase at every degree of freedom under a harmonic force, by modal superposition, with a modal breakdown showing which mode is actually carrying the response. Every natural frequency is a resonance, not just the first, and a load applied at a node of a mode cannot excite that mode at all — a real design lever, and the reason a shaker in the wrong place can miss a mode entirely. Damping is entered as modal ratios or a Rayleigh α/β pair, because modal superposition assumes classical damping, which a single discrete damper between two floors does not satisfy; the tool states that rather than assuming it of a matrix you handed it.

Try it: beam span 8, supports pin 0, roller 8, load udl 5 from 0 to 8 → reactions 20 kN each, Mmax = 40 kN·m at mid-span. Stress state σ₁ = 100, σ₂ = 60 → 20 MPa in-plane maximum shear but 50 in truth, because the zero out-of-plane principal stress lies outside the in-plane pair — and it is the second number the bar yields at.

Inserts: the worked result as text, tables, and figures — shear and bending-moment diagrams, Mohr's circle, Bode plots, step responses and concentration curves. Honest limits: beams are Euler–Bernoulli (no shear deformation) though their supports may be elastic or settling, trusses are pin-jointed, planar and determinate only, torsion is circular shafts only, circuits are linear and lumped with no transient analysis, control is linear time-invariant and single-input single-output, multi-DOF forced response assumes classical (proportional) damping, and every fatigue life is an order of magnitude rather than a figure — identical specimens differ by a factor of three. There is no design code anywhere in this tool: it computes the mechanics, it does not tell you whether a member passes.

Sequence Map — open a file, draw an annotated map

FormatWhat you get

Align — pairwise sequence alignment

Compare two sequences and insert the alignment at the cursor. Needleman–Wunsch (global) and Smith–Waterman (local) with affine gaps — the algorithms EMBOSS needle and water run, at their default costs (BLOSUM62, gap open 10 / extend 0.5 for protein; +5/−4 for DNA). Paste plain sequence or FASTA; headers and whitespace are stripped. Sequence type auto-detects conservatively (DNA only when ≥90% ACGTUN).

Global forces an end-to-end alignment — use it when the two sequences are the same thing (a clone vs its reference). Local finds the best shared segment — use it when they share only a domain. The stats line reports identities, similarities, gaps, and 1-based spans; the ruler uses | (identical) and : (similar).

Percent identity is a fact about the alignment, not the sequences — it moves when you change the gap costs. Below ~25% identity (the “twilight zone”) two unrelated proteins still align convincingly, and JurisLab says so. The alignment inserts in a monospace font deliberately: a proportional font would silently break the column correspondence the ruler depends on.

DNA — nucleotide analysis

Live analysis of a DNA/RNA sequence (IUPAC codes accepted):

Virtual digest. Cut with the enzymes you choose and get fragment sizes, their spans and ends, and the bands a gel would actually resolve — two fragments within about 8% of each other co-migrate, and saying so beats predicting a gel you will not see. State the topology, because it changes the answer: n cuts give n fragments in a circular plasmid and n+1 in a linear molecule, and a single cut linearises rather than splitting.

  • Reverse complement (RNA-aware), complement, and transcription (T→U).
  • Translation in any of six frames; degenerate codons resolve when unambiguous (GCN → Ala), else X; optional stop-at-first-stop.
  • Base composition & GC%; a six-frame ORF finder with a minimum-length filter, coordinates 1-based on the (+) strand for both strands, inserted as a table.
  • Primer Tm by nearest-neighbour SantaLucia (1998) thermodynamics with salt and primer-concentration corrections (defaults 50 mM Na⁺, 0.25 µM); below 8 nt it falls back to the Wallace rule and says so.
  • Protein properties of the translation: MW (ProtParam masses), pI (EMBOSS pKa values), GRAVY (Kyte–Doolittle).
  • Restriction sites from a 122-enzyme table (both strands, IUPAC-degenerate, Type IIS), with cut positions and overhangs, unique cutters starred, and methylation warnings (Dam/Dcm/DpnI).
Try it: ATGGCCAAGCTTGATTAA → mRNA AUGGCCAAGCUUGAUUAA; +1 translation MAKLD*; reverse complement TTAATCAAGCTTGGCCAT; a HindIII site at A^AGCTT.
Primer Tm is meaningless without its conditions. The readout always echoes them, and warns that it assumes a perfectly matched duplex — no mismatches, hairpins or primer-dimers, and it says nothing about specificity.

Bio/Assay — kinetics, dose–response, binding & lab math

Pick one of 16 calculators. Four fit a curve with a shared Levenberg–Marquardt engine that reports parameters ± standard errors and R² and draws the fit over your data; the rest are closed-form lab maths. You never enter starting values — each fit seeds itself from a linearization.

Honest limits — what JurisLab does not do

Knowing where a tool stops is what makes the rest of it trustworthy.

  • It is a drafting aid. Verify every structure, formula, calculation and listing before filing or publishing. It is not a reviewer.
  • Predicted spectra are estimates, not measurements — see the Spectra warning above.
  • pKa detection is exact; aromatic acids/bases and aliphatic acids are substituent-corrected (Hammett/inductive, ±0.3–0.5), other groups use the typical group value. It’s a strong estimate, not a measurement.
  • The Solve/ODE tools say which answers are exact and which are numerical — exact for linear/quadratic roots, formula rearrangement, and integrals with a closed form; complete (every root, real and complex) for higher polynomials; numerical for transcendental equations, where only the real roots bracketed in the scanned range are reported. ODE solutions are numerical throughout — no closed-form ODEs, no boundary-value problems or PDEs.
  • IR predicts group frequencies, not the fingerprint region below ~1500 cm⁻¹.
  • UV-Vis uses the Woodward–Fieser rules, which have a defined domain; outside it, JurisLab says “transparent” instead of guessing.
  • Reaction is a layout tool — it doesn’t balance, predict, or check feasibility.
  • ST.26 listings need WIPO validation, and citations need a Bluebook check, before filing.
  • Word on the web / older Word: native equations need a recent Word. Where they aren’t available, JurisLab inserts formatted text instead and tells you it did.

Troubleshooting

SymptomWhat to do
Mac: “install.command can’t be opened” / “unidentified developer” / only Move to TrashRight-click the file → Open (not double-click). If it still won’t open, go to Apple menu → System Settings → Privacy & Security, scroll to Security, and click Open Anyway next to “install.command was blocked”, then confirm once more. This is Apple’s one-time approval; the installer only copies one file. The unzipped folder also has a START HERE file with a copy-paste fallback.
Windows: double-clicking install.bat does nothing, or opens NotepadRight-click install.ps1 → Run with PowerShell. If a “Windows protected your PC” box appears, click More info → Run anyway.
The add-in doesn’t appear after installingFully close and reopen Word — all windows, not just the document (on Mac, ⌘-Q). This is the usual cause. Also make sure you opened Word once before installing. Then look under Insert → Add-ins (Windows: Developer Add-ins).
The pane is blank or won’t loadYou need internet for the first load. If it’s still blank, close the pane and reopen it. If it persists, reinstall from the current pack — an older install can point at an address that no longer exists.
A banner says a new version is availableReload the pane (close and reopen it). You don’t need to reinstall — the add-in updates itself from the web.
“Couldn’t build an equation from that”The expression didn’t parse, so it inserted formatted text instead. Check for an unclosed bracket. The Examples & syntax panel shows the syntax for what you’re typing.
The preview shows an errorTrust it — that’s the preview doing its job. Nothing is inserted until you click Insert.
An ODE says it stalled or looks stiffSet the solver to Auto (or Implicit). If it still won’t finish, the solution may genuinely blow up in finite time — try a shorter range.
